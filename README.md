# Telegram-бот «умные напоминания»

Бот принимает текстовые и голосовые сообщения на естественном языке, понимает
относительное время («после работы», «за два часа до сна») на основе
сохранённого распорядка пользователя и доставляет напоминания точно в срок.
Понимание языка — локальная LLM **qwen3.5:4b** через Ollama, распознавание
речи — **Whisper (medium)**, хранение — **SQLite**.

## Возможности

- 📋 **Память о распорядке**: «Я работаю с 9 до 18, сплю с 23 до 7» — бот
  извлекает и сохраняет структурированный контекст.
- 🕐 **Относительное время**: «Когда приду на работу завтра — напомни
  позвонить клиенту» → напоминание на завтрашний `work_start`.
- ❓ **Уточняющие вопросы**: если распорядок неизвестен, бот спрашивает
  («Во сколько ты заканчиваешь работу?»), сохраняет ответ и создаёт напоминание.
- 🔁 **Периодические серии с условиями**: «Напоминай после работы каждый час
  пить воду, и так до двух часов до сна» → серия с конца рабочего дня, шаг
  1 час, до `sleep_start − 2ч`. Серия хранится **символически** (якоря на ключи
  контекста), поэтому при изменении распорядка пересчитывается автоматически.
- 📅 **Базовые напоминания**: по дню недели, по дате, по конкретному времени.
- 🎙 **Голосовые сообщения**: транскрибация Whisper'ом, дальше тот же конвейер.
- 🔐 **Доступ по белому списку**: бот можно закрыть для посторонних —
  администратор добавляет пользователей по Telegram ID (`/adduser <id>`).
- 💾 **Персистентность**: всё в SQLite; после перезапуска планировщик
  восстанавливает работу с первого же тика, просроченные напоминания
  отправляются с пометкой «просрочено», пропущенные срабатывания серий
  сворачиваются в одно уведомление.

## Архитектура

```
bot/
├── main.py        # точка входа: DI, запуск поллинга и планировщика
├── config.py      # конфигурация из .env
├── handlers.py    # команды, текст/голос, диспетчеризация действий LLM
├── llm.py         # клиент Ollama: JSON-режим, валидация схемы, ретраи
├── prompts.py     # системный промпт: дата/время, TZ, контекст, few-shot
├── rules.py       # движок правил серий: якоря, срабатывания, валидация
├── scheduler.py   # доставка в срок, догон после простоя (БД — истина)
├── transcribe.py  # Whisper в отдельном потоке, ленивая загрузка
└── db.py          # SQLite (aiosqlite): пользователи, напоминания, серии
```

### Разделение ответственности

| Детеминированный код | LLM (qwen3.5:4b) |
|---|---|
| приём сообщений, транскрибация | извлечение сути и времени из текста |
| валидация JSON и правил серий | преобразование относительного времени по контексту |
| планировщик, доставка точно в срок | извлечение фактов о распорядке |
| персистентность и восстановление | формулировка уточняющих вопросов |

LLM возвращает строго один JSON-объект (действие `save_context` /
`create_reminder` / `create_recurring` / `ask_clarification` /
`not_a_reminder`). Невалидный ответ отправляется модели обратно со списком
ошибок — до 3 попыток. В системный промпт передаются текущие дата/время,
часовой пояс и сохранённый контекст пользователя.

### Ключевые решения

- **aiogram 3** — полностью асинхронный фреймворк: HTTP-вызовы Ollama и
  ожидание Telegram не блокируют друг друга, встроенное DI внедряет
  зависимости в обработчики, маршрутизация фильтрами (`F.voice`, `Command`)
  чище, чем у python-telegram-bot.
- **SQLite** — нулевая эксплуатация, транзакционность, файл переживает
  перезапуск. Объёмы данных бота-напоминалки для SQLite ничтожны.
- **Планировщик без состояния в памяти** — вместо APScheduler простой цикл,
  который каждые 15 с читает БД. БД — единственный источник истины, поэтому
  «восстановление после рестарта» не отдельный механизм, а обычный первый тик.
- **Символические серии** — интервальная серия хранит не список моментов, а
  правило с якорями (`{"kind": "context", "key": "work_end"}`); времена
  вычисляются на каждом тике из актуального контекста, поэтому смена
  распорядка мгновенно пересчитывает серию.

## Что нужно установить

Полный список зависимостей для работы бота:

| Компонент | Зачем | Как установить |
|---|---|---|
| **Python 3.11+** | язык, на котором написан бот | `sudo apt install python3.11` / [python.org](https://www.python.org/downloads/) |
| **ffmpeg** | Whisper читает через него голосовые (.ogg) | `sudo apt install ffmpeg` (macOS: `brew install ffmpeg`) |
| **Ollama** | локальный сервер LLM | `curl -fsSL https://ollama.com/install.sh \| sh` |
| **Модель qwen3.5:4b** | разбор естественного языка | `ollama pull qwen3.5:4b` (~2.5 ГБ) |
| **Python-пакеты** | aiogram, aiosqlite, httpx, python-dotenv, openai-whisper (+PyTorch), tzdata | `pip install -r requirements.txt` |
| **Модель Whisper medium** | распознавание речи | скачается автоматически при первом голосовом (~1.5 ГБ) |
| **Токен Telegram-бота** | доступ к Telegram Bot API | получить у [@BotFather](https://t.me/BotFather), вписать в `.env` |

Ориентировочные требования: ~5 ГБ диска под модели и от 8 ГБ ОЗУ
(qwen3.5:4b и whisper-medium на CPU; с GPU всё заметно быстрее).
На слабой машине поставьте в `.env` `WHISPER_MODEL=small` или `base`.

## Установка по шагам

### 1. Системные зависимости

```bash
# ffmpeg нужен Whisper'у для чтения голосовых (.ogg)
sudo apt install ffmpeg        # Debian/Ubuntu
# brew install ffmpeg          # macOS
```

### 2. Ollama и модель

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3.5:4b
ollama serve   # если не запущена как сервис
```

Проверка: `curl http://localhost:11434/api/tags` должен вернуть JSON со
списком моделей, в котором есть `qwen3.5:4b`.

### 3. Python-окружение

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`openai-whisper` подтянет PyTorch; модель `medium` (~1.5 ГБ) скачается при
первом голосовом сообщении. Для слабых машин поставьте `WHISPER_MODEL=small`
или `base` в `.env`.

### 4. Конфигурация

```bash
cp .env.example .env
# впишите BOT_TOKEN (от @BotFather) в .env
```

Все параметры (`OLLAMA_URL`, `OLLAMA_MODEL`, `WHISPER_MODEL`, `DEFAULT_TZ`,
`DB_PATH`, `POLL_INTERVAL`) — в `.env.example`. Часовой пояс по умолчанию —
`Europe/Minsk`, каждый пользователь может сменить свой командой `/timezone`.

### 5. Запуск

```bash
python -m bot.main
```

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | приветствие и справка |
| `/list` | активные разовые напоминания и серии (с ближайшим срабатыванием) |
| `/delete` | удаление через инлайн-кнопки |
| `/context` | сохранённый распорядок и часовой пояс |
| `/timezone <IANA-имя>` | смена часового пояса, например `/timezone Europe/Moscow` |
| `/id` | показать свой Telegram ID |
| `/adduser <id>` | 👑 добавить пользователя в белый список (только админ) |
| `/removeuser <id>` | 👑 убрать пользователя из белого списка (только админ) |
| `/users` | 👑 показать админов и белый список (только админ) |
| `/log` | 👑 последние логи бота с постраничным листанием ⬅️➡️ (только админ) |

## Ограничение доступа по ID

По умолчанию бот открыт для всех. Чтобы закрыть его:

1. Впишите свой Telegram ID в `.env`: `ADMIN_USER_IDS=123456789`
   (узнать ID: команда `/id` у бота или @userinfobot; несколько админов —
   через запятую).
2. Перезапустите бота. Теперь доступ есть только у админов и белого списка.
3. Добавляйте пользователей на лету: `/adduser 987654321` (хранится в SQLite,
   переживает перезапуск), убирайте — `/removeuser 987654321`, смотрите
   список — `/users`. Статичный список можно также задать в `.env` через
   `ALLOWED_USER_IDS=111,222`.

Посторонний пользователь получает отказ с его Telegram ID — этот ID он может
прислать администратору.

## Политика пропущенных напоминаний

- Разовое напоминание, чей срок прошёл, пока бот лежал, отправляется при
  старте с пометкой **«⏰ Просрочено»** и исходным сроком.
- Срабатывание серии, опоздавшее меньше чем на 15 минут (`SERIES_GRACE`),
  отправляется как обычно; более старые не спамятся по одному, а
  сворачиваются в одно сообщение «пропущено N напоминаний серии».

## Статус обработки

На каждое текстовое/голосовое сообщение бот сразу отвечает статусным
сообщением и редактирует его по этапам: «распознаю голосовое» → «разбираю
запрос (LLM)» → «сохраняю». Когда обработка закончена, статусное сообщение
заменяется результирующим ответом (если Telegram не даёт отредактировать —
удаляется и отправляется новое). Бот никогда не оставляет сообщение без
ответа: любая внутренняя ошибка тоже показывается пользователю.

## Запуск на Windows

Всё проверено под Windows, порядок такой (PowerShell):

```powershell
# 1. Python 3.11+ с python.org (при установке отметить "Add python.exe to PATH")

# 2. ffmpeg — нужен Whisper'у для голосовых
winget install Gyan.FFmpeg
# после установки перезапустить терминал; проверка: ffmpeg -version

# 3. Ollama — установщик с https://ollama.com/download/windows, затем:
ollama pull qwen3.5:4b

# 4. Проект
cd Telegram-calendar
python -m venv .venv
.venv\Scripts\Activate.ps1        # в cmd: .venv\Scripts\activate.bat
pip install -r requirements.txt
copy .env.example .env            # вписать BOT_TOKEN и ADMIN_USER_IDS

# 5. Запуск
python -m bot.main
```

Особенности Windows, уже учтённые в коде:

- **`tzdata` обязателен** (есть в `requirements.txt`) — в Windows нет
  системной базы часовых поясов IANA; без него каждое сообщение падало бы
  с `ZoneInfoNotFoundError`. Бот проверяет это при старте.
- **ffmpeg проверяется при старте и перед транскрибацией** — если его нет
  в PATH, бот предупреждает в логе, а на голосовое отвечает понятной
  ошибкой (текстовые сообщения работают и без ffmpeg).
- **Первый запрос к LLM может идти минуты** — модель грузится в память;
  таймаут настраивается (`LLM_TIMEOUT`, по умолчанию 180 с).
- Остановка по `Ctrl+C` — штатная, без трейсбека; лог-файл пишется в
  UTF-8; пути и удаление временных файлов голосовых устойчивы к блокировкам
  файлов антивирусом.

## Диагностика («бот молчит / ничего не сохранилось»)

1. **Смотрите ответ бота на само сообщение** — теперь он есть всегда
   (статус → результат). «⚠️ Языковая модель недоступна» — не запущена
   Ollama или не скачана модель.
2. **Проверьте модель**: `ollama list` должен показывать `qwen3.5:4b`;
   при старте бот пишет в лог, доступна ли Ollama и найдена ли модель.
3. **Формат времени не проблема**: «16.30», «16-30», «7», «22» понимаются
   и приводятся к «16:30» / «07:00» и в коде, и в промпте модели.
4. **Логи**: все ключевые события (действие LLM, обновление контекста,
   создание напоминаний, невалидные ответы модели с их текстом) пишутся
   в stdout и в файл `data/bot.log` (путь — `LOG_FILE` в `.env`, ротация
   5 МБ × 3 файла); администратор может смотреть последние ~1000 записей
   прямо в Telegram командой `/log` (страницы листаются кнопками ⬅️/➡️,
   на краях соответствующая стрелка исчезает). При перезапуске бота /log
   подхватывает историю из файла.

## Обработка ошибок

- **Ollama недоступна** — бот отвечает «модель недоступна», продолжает
  работать (планировщик и команды не зависят от LLM).
- **Невалидный JSON от LLM** — до 3 повторных запросов с описанием ошибок,
  затем вежливый отказ.
- **Ошибка транскрибации** — понятное сообщение с просьбой повторить.
- **Ошибка отправки в Telegram** — напоминание остаётся `pending` и
  повторяется на следующем тике.

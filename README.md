# Telegram-бот «умные напоминания»

Бот принимает текстовые и голосовые сообщения на естественном языке, понимает
относительное время («после работы», «за два часа до сна») на основе
сохранённого распорядка пользователя и доставляет напоминания точно в срок.
Понимание языка — LLM через **облачный OpenAI-совместимый API** (по
умолчанию бесплатный **NVIDIA NIM**, `qwen/qwen3.5-122b-a10b`, с цепочкой
фолбэков на другие облачные модели), распознавание речи — облачный
**whisper-large-v3** (например, бесплатный Groq) или локальный Whisper,
хранение — **SQLite**. Весь функционал дополнительно доступен как
**Telegram Mini App** — веб-интерфейс, открывающийся прямо внутри Telegram.

## Возможности

- 📋 **Память о распорядке**: «Я работаю с 9 до 18, сплю с 23 до 7» — бот
  извлекает и сохраняет структурированный контекст. Значения могут быть
  условными: «По чётным дням работаю до 16:30, по нечётным — до 18» —
  серии, привязанные к work_end, сами подстраиваются под день. `/context`
  показывает всё человекочитаемо («Конец работы: 16:30 (по чётным числам);
  18:00 (по нечётным числам)»).
- 🗓 **Условия в сериях**: «Принимать витамины по чётным дням в 9:00»,
  «Каждую пятницу по чётным числам — сдать отчёт» — день недели и чётность
  числа комбинируются (логическое И). Окна-исключения: «Когда я на работе
  напоминай раз в час учить английский, но не в обеденное время» — обеденные
  срабатывания отбрасываются.
- ✏️ **Редактирование распорядка**: новое значение — просто сообщением
  («теперь работаю до 17»), удаление ключа — кнопкой 🗑 в `/context` или
  фразой («я больше не хожу в спортзал»).
- 🚦 **Очередь обработки**: сообщения одного пользователя обрабатываются
  строго по порядку, разных пользователей — параллельно; распознавание
  речи сериализовано (модель Whisper не потокобезопасна), запросы к LLM
  идут одновременно.
- 🔇 **Ошибки без лишних деталей**: обычный пользователь видит короткую
  категорию («ошибка распознавания речи: пустое сообщение»), подробности —
  только администратору и в логах.
- 🕐 **Относительное время**: «Когда приду на работу завтра — напомни
  позвонить клиенту» → напоминание на завтрашний `work_start`.
- ❓ **Уточняющие вопросы**: если распорядок неизвестен, бот спрашивает
  («Во сколько ты заканчиваешь работу?»), сохраняет ответ и создаёт напоминание.
- 🔁 **Периодические серии с условиями**: «Напоминай после работы каждый час
  пить воду, и так до двух часов до сна» → серия с конца рабочего дня, шаг
  1 час, до `sleep_start − 2ч`. Серия хранится **символически** (якоря на ключи
  контекста), поэтому при изменении распорядка пересчитывается автоматически.
- 📅 **Базовые напоминания**: по дню недели, по дате, по конкретному времени.
- ❓ **Условные напоминания**: «Если в 11:30 завтра не буду спать — напомни
  после обеда выпить таблетку». В момент проверки бот задаёт вопрос с
  кнопками «Да/Нет»; ответ «Да» до целевого времени создаёт напоминание,
  без ответа условие истекает (с уведомлением).
- 🌍 **Часовой пояс из разговора**: «Я из Минска» — пояс ставится по городу
  (LLM знает IANA-имя, плюс встроенный словарь городов); «У меня сейчас
  16:45» — пояс вычисляется по названному времени (хранится как UTC±HH:MM).
  После установки бот переспрашивает «у тебя сейчас HH:MM, верно?».
- 🤔 **Защита от искажения текста**: если LLM заменила слова напоминания
  (а не просто исправила форму), бот показывает исходное сообщение и своё
  понимание и просит подтвердить кнопками, прежде чем создавать.
- 📅 **Дни недели**: в промпт передаётся календарь ближайших 8 дней;
  «в субботу» = ближайшая, «в следующую субботу» = на следующей неделе
  (это же понимает детерминированный парсер).
- 🎙 **Голосовые сообщения**: транскрибация Whisper'ом, дальше тот же конвейер.
- 🔐 **Доступ по белому списку**: бот можно закрыть для посторонних —
  администратор добавляет пользователей по Telegram ID (`/adduser <id>`).
- 💾 **Персистентность**: всё в SQLite; после перезапуска планировщик
  восстанавливает работу с первого же тика, просроченные напоминания
  отправляются с пометкой «просрочено», пропущенные срабатывания серий
  сворачиваются в одно уведомление.

## Архитектура

```
bot/
├── main.py         # точка входа: DI, запуск поллинга, планировщика и Mini App
├── config.py       # конфигурация из .env
├── handlers.py     # команды, текст/голос, диспетчеризация действий LLM
├── nlpipe.py       # тот же конвейер LLM без привязки к Telegram — для Mini App
├── webapp.py       # HTTP-API мини-приложения (aiohttp) + аутентификация
├── telegram_auth.py# проверка подписи Telegram WebApp initData
├── llm.py          # OpenAI-совместимый LLM-клиент: цепочка моделей, ретраи
├── prompts.py      # системный промпт: дата/время, TZ, контекст, few-shot
├── rules.py        # движок правил серий: якоря, срабатывания, валидация
├── timeparse.py    # детерминированный разбор «через 5 минут», «завтра в 9»…
├── postprocess.py  # санитайзер: жёсткая проверка ответа LLM по тексту
├── tzutil.py        # часовые пояса: города, смещения, разбор ввода
├── scheduler.py    # доставка в срок, догон после простоя (БД — истина)
├── transcribe.py   # облачный ASR + локальный Whisper-фолбэк
└── db.py           # SQLite (aiosqlite): пользователи, напоминания, серии

webapp/              # статика Mini App: index.html, app.js, style.css
```

### Разделение ответственности

| Детеминированный код | LLM (через API) |
|---|---|
| приём сообщений, транскрибация | извлечение сути и времени из текста |
| валидация JSON и правил серий | преобразование относительного времени по контексту |
| планировщик, доставка точно в срок | извлечение фактов о распорядке |
| персистентность и восстановление | формулировка уточняющих вопросов |

LLM возвращает строго один JSON-объект (действие `save_context` /
`create_reminder` / `create_recurring` / `ask_clarification` /
`not_a_reminder`). Невалидный ответ отправляется модели обратно со списком
ошибок — до 3 попыток. В системный промпт передаются текущие дата/время,
часовой пояс и сохранённый контекст пользователя.

**Двухэтапный разбор запроса.** Первый вызов LLM — только разметка:
сообщение делится на блоки (задача / время / повторение / условие / факт /
город), причём каждый блок обязан быть **дословным фрагментом** сообщения —
это проверяется кодом (перефразированные блоки бракуются и уходят на
повтор). Простые случаи (задача + время; задача + «каждый вторник в 10»)
дальше собираются в действие чисто детерминированно (`postprocess.
action_from_blocks`) — второй вызов LLM не нужен, а текст напоминания
гарантированно состоит из слов пользователя. Сложные случаи (условия,
интервальные серии с якорями, факты о распорядке) идут во второй вызов, в
промпт которого вкладывается готовая разметка. Затем каждую составляющую
обрабатывает свой метод:
простые выражения («через 5 минут», «сегодня в 19:30», «завтра в 7»,
«в понедельник в 10», «15 августа в 12:00») вычисляет детерминированный
парсер `timeparse.py` — арифметика времени не доверяется маленькой модели;
контекстные («после работы», «за час до сна») вычисляет LLM по сохранённому
распорядку. Дополнительные страховки: если модель переспрашивает данные,
которые уже есть в контексте, бот делает корректирующий повтор с подсказкой;
после ответа на уточняющий вопрос бот автоматически возвращается к
исходному запросу и доводит его до конца; классификация сверяется с текстом
детерминированно — «через 5 минут» без слов «каждый/ежедневно/раз в…» не
может стать серией (и наоборот), при расхождении делается корректирующий
повтор.

**Комбинированные запросы.** «Напомни через час, а потом каждый день» —
LLM возвращает `multi` со списком действий (разовое напоминание + серия),
бот выполняет их по очереди и отвечает одним сообщением. Серия при этом
не дублирует разовое: её отсчёт начинается после первого напоминания.

### Ключевые решения

- **aiogram 3** — полностью асинхронный фреймворк: HTTP-вызовы LLM API и
  ожидание Telegram не блокируют друг друга, встроенное DI внедряет
  зависимости в обработчики, маршрутизация фильтрами (`F.voice`, `Command`)
  чище, чем у python-telegram-bot.
- **SQLite** — нулевая эксплуатация, транзакционность, файл переживает
  перезапуск. Объёмы данных бота-напоминалки для SQLite ничтожны.
- **Планировщик без состояния в памяти** — вместо APScheduler простой цикл,
  который каждые 15 с читает БД. БД — единственный источник истины, поэтому
  «восстановление после рестарта» не отдельный механизм, а обычный первый тик.
- **Символические серии** — интервальная серия хранит не список моментов, а
  правило с якорями (`{"kind": "context", "key": "work_end"}`); времена
  вычисляются на каждом тике из актуального контекста, поэтому смена
  распорядка мгновенно пересчитывает серию.

## Установка по шагам

### 1. Системные зависимости

```bash
# ffmpeg нужен Whisper'у для чтения голосовых (.ogg)
sudo apt install ffmpeg        # Debian/Ubuntu
# brew install ffmpeg          # macOS
```

### 2. Ключи API

- **LLM**: на [build.nvidia.com](https://build.nvidia.com) сгенерируйте ключ
  `nvapi-…` и впишите его в `.env` (`LLM_API_KEY`). Модель по умолчанию —
  `qwen/qwen3.5-122b-a10b` (бесплатные кредиты); менять — `LLM_MODELS`.
- **Голосовые** (опционально): бесплатный ключ на
  [console.groq.com](https://console.groq.com), затем в `.env`:
  `ASR_API_BASE=https://api.groq.com/openai/v1`, `ASR_API_KEY=gsk_…`.
  Без этого используется локальный Whisper (нужен ffmpeg).

Проверка LLM: `curl -H "Authorization: Bearer $LLM_API_KEY"
https://integrate.api.nvidia.com/v1/models` — вернёт список моделей.

> **Гео-блокировка**: NVIDIA API недоступен из некоторых стран (Беларусь,
> Россия) — «All connection attempts failed». Решения: VPN/прокси на машине
> бота, либо другой облачный OpenAI-совместимый провайдер — основным
> (`LLM_API_BASE`) или запасным (`LLM_FALLBACK_API_BASE`), например
> OpenRouter (openrouter.ai, есть бесплатные модели).

**Отказоустойчивость**: `LLM_MODELS` — цепочка моделей; каждая пробуется
до `LLM_ATTEMPTS_PER_MODEL` раз (с паузами), затем следующая, затем модели
запасного провайдера. Последняя работавшая запоминается и пробуется первой.

### 3. Python-окружение

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`openai-whisper` подтянет PyTorch; модель `medium` (~1.5 ГБ) скачается при
первом голосовом сообщении. Для слабых машин поставьте `WHISPER_MODEL=small`
или `base` в `.env`.

### 4. Конфигурация

```bash
cp .env.example .env
# впишите BOT_TOKEN (от @BotFather) в .env
```

Все параметры (`LLM_API_BASE`, `LLM_MODELS`, `ASR_API_BASE`, `WHISPER_MODEL`,
`DEFAULT_TZ`, `DB_PATH`, `POLL_INTERVAL` и другие) — в `.env.example`. Часовой пояс по умолчанию —
`Europe/Minsk`, каждый пользователь может сменить свой командой `/timezone`.

### 5. Запуск

```bash
python -m bot.main
```

## Telegram Mini App

Весь функционал бота — напоминания, серии, условные, распорядок, часовой
пояс — доступен в виде веб-интерфейса, открывающегося прямо внутри
Telegram (кнопка меню или команда `/app`). Реализация:

- **Бэкенд** — `bot/webapp.py`, HTTP-сервер на aiohttp, поднимается в том
  же процессе и на том же event loop, что и сам бот (`bot/main.py`).
  REST API переиспользует существующую бизнес-логику (`bot/db.py`,
  `bot/handlers.py`, `bot/postprocess.py`) — никакой логики не продублировано,
  кроме тонкой маршрутизации ответа LLM в JSON вместо Telegram-сообщений
  (`bot/nlpipe.py`).
- **Фронтенд** — `webapp/` (чистые HTML/CSS/JS без сборки), использует
  официальный Telegram Web App JS SDK, подхватывает цветовую тему
  Telegram (`themeParams`) для нативного вида в светлой и тёмной теме.
- **Аутентификация** — Telegram WebApp `initData`: фронтенд при каждом
  запросе шлёт заголовок `Authorization: tma <initData>`, сервер проверяет
  HMAC-подпись бот-токеном (`bot/telegram_auth.py`, официальный алгоритм
  Telegram) и достаёт `user_id` — подделать чужой ID нельзя, не зная токен
  бота. Тот же белый список доступа (`ADMIN_USER_IDS`/`/adduser`), что и у
  самого бота.
- **API**: `GET /api/state` (снимок всего: распорядок, напоминания, серии,
  условные, часовой пояс), `POST/DELETE /api/context`, `POST /api/timezone`,
  `DELETE /api/reminders|series|conditionals/{id}`, `POST /api/message`
  (произвольный текст — тот же LLM-конвейер, что и в чате: «Напомни завтра
  в 9 позвонить клиенту» создаст напоминание прямо из мини-аппа).

### Настройка

**Обязательное условие Telegram: публичный HTTPS-адрес.** Без него кнопка
мини-аппа в боте работать не будет — таково требование самого Telegram,
не этого проекта.

```bash
# .env
WEBAPP_ENABLED=1
WEBAPP_HOST=0.0.0.0
WEBAPP_PORT=8080
WEBAPP_URL=https://ваш-домен-или-туннель
```

Для локальной разработки без своего домена — любой HTTPS-туннель до
`WEBAPP_HOST:WEBAPP_PORT`, например Cloudflare Tunnel (`cloudflared tunnel
--url http://localhost:8080`) или ngrok. В проде — обычный реверс-прокси
(Caddy/nginx) с TLS перед портом мини-аппа.

После перезапуска бот сам выставит `WEBAPP_URL` кнопкой меню Telegram
(рядом со строкой ввода) и ответит на `/app` инлайн-кнопкой «Открыть
приложение».

### Локальная проверка без Telegram

Настоящую аутентификацию (`initData`) не подделать без бот-токена, поэтому
для ручной проверки API без реального Telegram-клиента есть обходной путь
для разработки — **по умолчанию выключен**:

```bash
WEBAPP_ALLOW_DEV_AUTH=1   # только для локальной разработки!
```

При включённом флаге API принимает заголовок `X-Dev-User-Id: <id>` вместо
подписи Telegram:

```bash
curl -H "X-Dev-User-Id: 123456789" http://localhost:8080/api/state
```

> ⚠️ Обязательно выключите (`WEBAPP_ALLOW_DEV_AUTH=0`, по умолчанию) на
> продакшене — с этим флагом любой, кто достучится до сервера, может
> представиться любым `user_id`.

### Честно об уровне проверки

Backend (маршруты, аутентификация, вся бизнес-логика) покрыт
автоматическими тестами, включая полный HTTP-цикл через `aiohttp` в
изолированном процессе. Фронтенд (`webapp/*.js|css|html`) написан по
официальной спецификации Telegram Mini Apps и проверен статически, но
**визуально не протестирован в живом Telegram-клиенте** — для этого нужен
реальный телефон и публичный HTTPS-адрес, которых в этой среде разработки
нет. Перед боевым использованием стоит открыть `/app` на своём телефоне и
пройтись по всем разделам.

## Ограничение доступа по ID

По умолчанию бот открыт для всех. Чтобы закрыть его:

1. Впишите свой Telegram ID в `.env`: `ADMIN_USER_IDS=123456789`
   (узнать ID: команда `/id` у бота или @userinfobot; несколько админов —
   через запятую).
2. Перезапустите бота. Теперь доступ есть только у админов и белого списка.
3. Добавляйте пользователей на лету: `/adduser 987654321` (хранится в SQLite,
   переживает перезапуск), убирайте — `/removeuser 987654321`, смотрите
   список — `/users`. Статичный список можно также задать в `.env` через
   `ALLOWED_USER_IDS=111,222`.

Посторонний пользователь получает отказ с его Telegram ID — этот ID он может
прислать администратору.

## Политика пропущенных напоминаний

- Разовое напоминание, чей срок прошёл, пока бот лежал, отправляется при
  старте с пометкой **«⏰ Просрочено»** и исходным сроком.
- Срабатывание серии, опоздавшее меньше чем на 15 минут (`SERIES_GRACE`),
  отправляется как обычно; более старые не спамятся по одному, а
  сворачиваются в одно сообщение «пропущено N напоминаний серии».

## Статус обработки

На каждое текстовое/голосовое сообщение бот сразу отвечает статусным
сообщением и редактирует его по этапам: «распознаю голосовое» → «разбираю
запрос (LLM)» → «сохраняю». Когда обработка закончена, статусное сообщение
заменяется результирующим ответом (если Telegram не даёт отредактировать —
удаляется и отправляется новое). Бот никогда не оставляет сообщение без
ответа: любая внутренняя ошибка тоже показывается пользователю.

## Запуск на Windows

Всё проверено под Windows, порядок такой (PowerShell):

```powershell
# 1. Python 3.11+ с python.org (при установке отметить "Add python.exe to PATH")

# 2. ffmpeg — нужен Whisper'у для голосовых
winget install Gyan.FFmpeg
# после установки перезапустить терминал; проверка: ffmpeg -version

# 3. Ключи API: nvapi-… с build.nvidia.com (LLM) и, для голосовых,
#    gsk_… с console.groq.com — вписать в .env

# 4. Проект
cd Telegram-calendar
python -m venv .venv
.venv\Scripts\Activate.ps1        # в cmd: .venv\Scripts\activate.bat
pip install -r requirements.txt
copy .env.example .env            # вписать BOT_TOKEN и ADMIN_USER_IDS

# 5. Запуск
python -m bot.main
```

Особенности Windows, уже учтённые в коде:

- **`tzdata` обязателен** (есть в `requirements.txt`) — в Windows нет
  системной базы часовых поясов IANA; без него каждое сообщение падало бы
  с `ZoneInfoNotFoundError`. Бот проверяет это при старте.
- **ffmpeg проверяется при старте и перед транскрибацией** — если его нет
  в PATH, бот предупреждает в логе, а на голосовое отвечает понятной
  ошибкой (текстовые сообщения работают и без ffmpeg).
- **Первый запрос к LLM может идти минуты** — модель грузится в память;
  таймаут настраивается (`LLM_TIMEOUT`, по умолчанию 180 с).
- Остановка по `Ctrl+C` — штатная, без трейсбека; лог-файл пишется в
  UTF-8; пути и удаление временных файлов голосовых устойчивы к блокировкам
  файлов антивирусом.

## Диагностика («бот молчит / ничего не сохранилось»)

1. **Смотрите ответ бота на само сообщение** — теперь он есть всегда
   (статус → результат). «⚠️ Языковая модель недоступна» — не запущена
   LLM API (проверь LLM_API_BASE/LLM_API_KEY) или неверная модель.
2. **Проверьте модель**: при старте бот пишет в лог, доступен ли LLM API
   и найдена ли модель LLM_MODEL в списке /models.
3. **Доступность проверяется быстро, а не долго**: соединение с провайдером
   имеет отдельный короткий таймаут (`LLM_CONNECT_TIMEOUT`, по умолчанию
   10 с) — заблокированный/недоступный хост (например, гео-блок NVIDIA)
   отваливается за секунды, а не ждёт полный `LLM_TIMEOUT`, как медленно
   отвечающая модель. После `LLM_ATTEMPTS_PER_MODEL` неудачных попыток
   модель помечается недоступной на `LLM_COOLDOWN` секунд (по умолчанию
   120) и на следующих сообщениях пропускается без единой попытки — сразу
   пробуется следующая модель в цепочке `LLM_MODELS` (и затем запасной
   провайдер `LLM_FALLBACK_API_BASE`, если задан). Это же относится к
   облачному ASR: сетевой сбой (не ответ сервиса, а именно недоступность)
   автоматически откатывается на локальный Whisper, если он установлен.
4. **Формат времени не проблема**: «16.30», «16-30», «7», «22» понимаются
   и приводятся к «16:30» / «07:00» и в коде, и в промпте модели.
5. **Логи**: все ключевые события (действие LLM, обновление контекста,
   создание напоминаний, невалидные ответы модели с их текстом) пишутся
   в stdout и в файл `data/bot.log` (путь — `LOG_FILE` в `.env`, ротация
   5 МБ × 3 файла); администратор может смотреть последние ~1000 записей
   прямо в Telegram командой `/log` (страницы листаются кнопками ⬅️/➡️,
   на краях соответствующая стрелка исчезает). При перезапуске бота /log
   подхватывает историю из файла.

## Обработка ошибок

- **LLM API недоступен** — бот отвечает «сервис недоступен», продолжает
  работать (планировщик и команды не зависят от LLM).
- **Невалидный JSON от LLM** — до 3 повторных запросов с описанием ошибок,
  затем вежливый отказ.
- **Ошибка транскрибации** — понятное сообщение с просьбой повторить.
- **Ошибка отправки в Telegram** — напоминание остаётся `pending` и
  повторяется на следующем тике.
